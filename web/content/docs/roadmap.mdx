## Available application source

| Component | Current implementation |
| --- | --- |
| Unified demo | One `/demo` with buyer/seller/arbiter views; legacy protected URL redirects |
| Payment asset | Official Circle Stellar testnet USDC; trustline preparation and external faucet |
| v1 protected contract | Existing fee-free testnet deployment; independent claim review/disputes/fallback |
| v2 protected contract | Separate source: scoped authenticated quotes, separate reserves, per-case caps, fee earning/returns |
| Local SDK | v1/v2 term encoding, exact funding signatures, quote validation and typed lifecycle |
| Local case service | Wallet-authenticated private evidence, retained versions and SQLite history |
| Transaction recovery | Durable hashes before wallet broadcast and confirmation reconciliation |
| Deadline execution | Optional local settlement/fallback worker with durable per-claim jobs |
| Basic auth-capture | Separate historical contract/integration reference |

## Release boundary

V2 source is **not** an upgrade to the recorded v1 deployment. It needs a separately reviewed build, deployment, matching configuration and network verification. The demo defaults to fee-free v1 until that happens.

This repository does not claim a published protected npm package, standardized upstream protected x402 wire extension, managed public facilitator, production evidence service, independent audit or mainnet readiness. Integration/service design pages describe those broader responsibilities. Local code and tests do not establish that a hosted service is operating.

## Verification and remaining operations

Use [setup](/docs/setup), [the unified walkthrough](/docs/quickstart) and [local SDK](/docs/testnet/sdk). Operators still need managed backups/retention, availability monitoring, key management, archive restoration and release review. A testnet reset or an archived record requires explicit reconciliation; it does not change the original agreement.
