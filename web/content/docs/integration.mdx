---
title: x402 payment negotiation
description: Connect protected payments to an API request, from the offer through delivery and settlement.
---
**Protected x402 negotiation is not fully implemented yet.** The flow below describes how the integration will work. The protected HTTP schema and compatibility rules will be published with the integration release.

## Receive the payment offer

When an API route requires payment, the resource server will return HTTP 402 with its supported network, asset, escrow contract and protected-payment capability. The buyer or agent will choose a compatible route and inspect the agreement before signing.

A buyer requiring review and dispute resolution will reject a basic-only offer. Basic auth-capture and protected settlement have different authorization and finalization rules.

## Agree and fund

The buyer integration will validate delivery and pricing criteria, work budget, deadlines, arbiters, fallback and fee limits. Both parties will authorize the complete terms. The buyer will fund principal and any accepted protocol and arbitration reserves under the agreed contract version.

The application will wait for funding confirmation before treating the budget as available. An offer, signature or queued transaction alone will not prove funding.

## Invoke the API and record delivery

The consumer will call the resource with its payment context. The seller will meter the work, return a usage or delivery receipt and submit a claim for the corresponding amount. The client will compare that receipt with the accepted pricing criteria and claim.

Receipts and delivery bodies remain offchain. Their onchain commitments let participants verify that the material being reviewed matches the recorded claim; a hash does not prove delivery quality.

## Review and settle

The buyer can accept a recorded claim, or either party can dispute it before review closes. An undisputed claim becomes eligible for settlement after review. A dispute follows the evidence, ruling and fallback process defined by the funded agreement.

Receiving an API response does not itself finalize payment. Each claim settles through the [payment lifecycle](/docs/protected/lifecycle).

## Build against compatible interfaces

The integration release will define payment requirements, payloads, receipts, capability discovery and error responses. SDK and facilitator compatibility checks will identify the supported contract and schema before signing. See [SDK integration](/docs/sdk) and [facilitator execution](/docs/services/facilitator) for their responsibilities.

For the separate spending-hold flow, see [basic x402 integration](/docs/basic/integration).
