## Core lifecycle operations

Protected escrow uses the following lifecycle operations. The payment’s contract version determines its term encoding and whether it includes fee reserves.

| Operation | Authority | Effect |
| --- | --- | --- |
| `authorize(terms)` | Buyer and seller | Fund the agreed budget; return payment ID |
| `claim(payment_id, amount, delivery_hash)` | Seller | Reserve available principal and start review |
| `accept(payment_id, claim_id, commitment)` | Buyer | Pay that exact eligible claim |
| `settle(payment_id, claim_id)` | Anyone | Pay an undisputed claim after review |
| `dispute(payment_id, claim_id, party, evidence_hash)` | Named party | Open a claim case before review ends |
| `submit_evidence(payment_id, claim_id, party, evidence_hash)` | Named party | Update evidence before response closes |
| `rule(payment_id, claim_id, seller_amount, expected_revision)` | Current arbiter | Pay a bounded award and return the remainder |
| `finalize_fallback(payment_id, claim_id)` | Anyone | Apply signed allocation after final timeout |
| `reclaim(payment_id)` | Buyer | Return eligible unused funds after session expiry |
| `void_unclaimed(payment_id)` | Seller | Return unused funds early |

## Fee-capable behavior

Protected escrow validates accepted quotes, collects separate reserves, allocates fee capacity to claims, enforces per-case and total caps, pays earned fees once and returns unearned funds. All settlement, cancellation and direct-action paths must follow those rules.

A claim cannot consume another claim's principal or fee allocation. Expiry cannot release capacity needed by a pending case. There is no unrestricted protected `capture` operation that bypasses review or arbitration.

## Reads and finality

Read operations include `payment_terms`, `payment_state`, `claim_state`, `case_arbiter`, `default_arbiter` and `payment_hash`. Additional operations are `version`, `fee_quote` and `quote_scope`, plus the arbiter-authorized `register_quote` mutation. Versioned payment and claim state includes the fee balances needed for reconciliation.

Use the canonical [term encoding](/docs/reference/terms) and [quote encoding](/docs/protected/quotes#quote-encoding) when preparing signatures.

Claims and disputes must be recorded before their applicable closing deadlines. A ruling requires current authority and revision after evidence closes. At the final deadline, fallback becomes eligible. Every transition requires a transaction and a finalized claim cannot pay twice.
